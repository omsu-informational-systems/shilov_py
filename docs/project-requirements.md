# Спецификация требований, ограничений и рисков

## 1. Функциональные требования (FR)
- **FR-1 (Регистрация):** Сервис обязан при старте сформировать событие `account.registration.request` с корректной версией схемы (`1.0`), указать в `secretKey` выданный платформенный ключ и дождаться в топике `account.registration.result` подтверждения со статусом `REGISTERED`.
- **FR-2 (Обработка отказа):** При получении статуса `REJECTED` сервис обязан зафиксировать причину в журнале с уровнем `ERROR`, выставить статус `DOWN` и заблокировать чтение свечей и отправку торговых решений.
- **FR-3 (Сигнал состояния):** После регистрации сервис обязан с периодичностью раз в 5 секунд отправлять событие `account.service.heartbeat` со стабильными идентификаторами, `instanceId`, метриками обработанных свечей и номером последнего среза.
- **FR-4 (Валидация входящего потока):** До передачи рыночных данных в логику сервис обязан проверить целостность конверта сообщения и наличие обязательных атрибутов свечи (`eventId`, `runId`, `sequenceNumber`, `instrument.ticker`, цены OHLC).
- **FR-5 (Публикация рекомендации HOLD):** На каждое валидное событие `market.candle.closed` сервис обязан сформировать и отправить в топик `strategy.recommendation.created` событие с сигналом `HOLD`, `confidence: 0`, `suggestedQuantity: 0`, сохранив цепочку связывания через `correlationId`, `causationId` и `sourceEventId`.
- **FR-6 (Прием результатов исполнения):** Сервис обязан вычитывать топик `strategy.recommendation.result`, фильтровать собственные сообщения по `accountId` и сопоставлять их с принятыми решениями через `recommendationId`.
- **FR-7 (Контроль жизнеспособности):** Предоставление неавторизованного HTTP-эндпоинта `GET /health`, возвращающего статус сервиса (`UP`/`DEGRADED`) и состояние подключения к брокеру Kafka.

## 2. Нефункциональные требования (NFR)
- **NFR-1 (Гарантия доставки At-Least-Once):** Ручной коммит смещения в Kafka (`enable.auto.commit = false`) выполняется строго синхронно после подтвержденной брокером отправки исходящего сообщения (`producer.flush()`).
- **NFR-2 (Идемпотентность):** Повторная доставка события с ранее обработанным `eventId` не должна вызывать повторную генерацию торговой рекомендации или искажать внутренние счетчики.
- **NFR-3 (Производительность и бюджет времени):** Время внутренней обработки одной свечи (`processingTimeMs`) не должно превышать 50 мс, чтобы гарантированно укладываться в окно сбора рекомендаций платформы.
- **NFR-4 (Информационная безопасность):** Запрещено логировать или передавать наружу значения `secretKey`, пароль брокера Kafka и детальные трассировки стека с конфиденциальными параметрами.
- **NFR-5 (Отказоустойчивость):** Временный обрыв TCP-соединения с брокером или перезапуск Kafka не должны приводить к аварийному завершению процесса приложения (`crash`). Сервис обязан выполнять повторные попытки подключения с интервалом в 5 секунд.

## 3. Ограничения (Constraints)
- **C-1 (Сетевой протокол):** Подключение к брокеру `omsu.7bits.it:9094` исключительно через `SASL_SSL` с механизмом `SCRAM-SHA-256`.
- **C-2 (Типы данных денег):** Все цены (`open`, `high`, `low`, `close`) в контрактах передаются десятичными строками; во внутренних расчетах запрещено использовать числа с плавающей точкой `float` во избежание потери точности.
- **C-3 (Изоляция очередей):** Для чтения свечей сервис обязан использовать уникальный технический идентификатор `group.id`, не пересекающийся с другими студентами.

## 4. Допущения (Assumptions)
- **A-1:** Платформа преподавателя берет на себя исполнение сделок, расчет маржинальных требований, комиссий и учет консенсуса группы.
- **A-2:** Пропуск номера `sequenceNumber` по конкретному инструменту допустим и может являться следствием отсутствия рыночных сделок в данном временном срезе, а не сбоем транспортного уровня.

## 5. Риски и меры по их снижению (Risks)
- **R-1 (Исключение из группы Kafka по таймауту):** Зависание обработки сообщения на время свыше `max.poll.interval.ms` (300 000 мс) приводит к потере партиций.  
  *Мера:* Вынесение синхронного `poll()` в изолированный воркер, исключение тяжелых блокирующих вызовов в цикле чтения.
- **R-2 (Опоздание рекомендации):** Задержка сети приводит к доставке ответа за пределами окна сбора платформы.  
  *Мера:* Немедленная отправка решения без ожидания следующей свечи, замер `processingTimeMs`.
- **R-3 (Утечка учетных данных):** Случайный коммит `.env` в публичный репозиторий.  
  *Мера:* Добавление `.env` в `.gitignore` до первого коммита, чтение настроек через `os.environ`.
